## 一、功能概述

为 New API 项目成功实现了完整的短信登录、手机号绑定和密码重置功能，包含以下核心能力：

### 1.1 核心功能（7个API接口）

| 接口 | 端点 | 权限 | 功能描述 |
|------|------|------|----------|
| 发送登录验证码 | `POST /api/user/send-sms-code` | 无需登录 | 发送短信验证码用于登录 |
| 短信登录 | `POST /api/user/sms-login` | 无需登录 | 验证码登录，支持自动注册 |
| 发送绑定验证码 | `POST /api/user/self/send-bind-code` | 需要登录 | 为已登录用户发送绑定验证码 |
| 绑定手机号 | `POST /api/user/self/bind-mobile` | 需要登录 | 将手机号绑定到当前账号 |
| 解绑手机号 | `POST /api/user/self/unbind-mobile` | 需要登录 | 解除手机号绑定 |
| 发送重置验证码 | `POST /api/user/send-reset-code` | 无需登录 | 发送验证码用于密码重置 |
| 重置密码 | `POST /api/user/reset-password` | 无需登录 | 通过验证码重置密码 |

### 1.2 应用场景

1. **新用户注册**：首次使用手机号登录，自动创建账号
2. **已有用户绑定**：密码登录用户可绑定手机号，之后可用手机号登录
3. **忘记密码**：通过已绑定手机号重置密码
4. **多终端登录**：手机号作为统一的登录凭证

## 三、数据库设计

### 3.1 User 表变更

```sql
-- 新增字段
ALTER TABLE users ADD COLUMN mobile VARCHAR(16);
ALTER TABLE users ADD INDEX idx_mobile (mobile);
```

**字段说明**：
- `mobile`: 手机号，可为NULL（保证向后兼容）
- 索引：`idx_mobile` 用于快速查询

### 3.2 短信验证码表（sms_codes）

```sql
CREATE TABLE sms_codes (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    mobile VARCHAR(16) NOT NULL,
    code VARCHAR(10) NOT NULL,
    scene INT NOT NULL,           -- 1=登录, 2=绑定, 3=重置
    create_ip VARCHAR(45),
    today_index INT DEFAULT 1,    -- 今日发送次数
    used BOOLEAN DEFAULT FALSE,
    used_time DATETIME,
    used_ip VARCHAR(45),
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    deleted_at DATETIME,

    INDEX idx_mobile (mobile),
    INDEX idx_mobile_scene_code (mobile, scene, code),
    INDEX idx_created_at (created_at)
);
```

**场景常量**：
- `SmsSceneLogin = 1` - 登录/注册
- `SmsSceneBind = 2` - 绑定手机号
- `SmsSceneReset = 3` - 密码重置

### 3.3 短信日志表（sms_logs）

```sql
CREATE TABLE sms_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    template_code VARCHAR(30),     -- 阿里云模板code
    mobile VARCHAR(16) NOT NULL,
    user_id BIGINT,
    send_status INT,               -- 0=待发送, 1=成功, 2=失败
    send_time DATETIME,
    api_send_code VARCHAR(64),     -- 阿里云返回码
    api_send_msg VARCHAR(255),     -- 阿里云返回消息
    api_request_id VARCHAR(128),   -- 请求ID
    api_serial_no VARCHAR(128),    -- BizId
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    deleted_at DATETIME,

    INDEX idx_mobile (mobile),
    INDEX idx_user_id (user_id)
);
```

## 四、核心业务逻辑

### 4.1 验证码生成流程

```go
// 1. 生成6位随机数字
code := rand.Intn(1000000)
formatted := fmt.Sprintf("%06d", code)

// 2. 检查发送频率
- 60秒内不允许重复发送同一手机号
- 每日最多发送10次（可配置）

// 3. 创建验证码记录
smsCode := &SmsCode{
    Mobile:     mobile,
    Code:       code,
    Scene:      scene,
    CreateIp:   clientIp,
    TodayIndex: todayIndex,
    Used:       false,
}

// 4. 调用阿里云短信API
err := SendAliyunSMS(mobile, map[string]string{"code": code})

// 5. 记录发送日志
smsLog := &SmsLog{
    Mobile:       mobile,
    SendStatus:   status,
    TemplateCode: templateCode,
}
```

### 4.2 验证码验证流程

```go
// 1. 查询最新的未使用验证码
SELECT * FROM sms_codes
WHERE mobile = ? AND code = ? AND scene = ? AND used = false
ORDER BY created_at DESC LIMIT 1

// 2. 检查是否过期（5分钟）
if time.Since(smsCode.CreatedAt) > 5*time.Minute {
    return errors.New("验证码已过期")
}

// 3. 标记为已使用
UPDATE sms_codes
SET used = true, used_time = NOW(), used_ip = ?
WHERE id = ?
```

### 4.3 自动注册流程

```go
// 1. 验证验证码
err := ValidateAndUseSmsCode(mobile, code, SmsSceneLogin, clientIp)

// 2. 查询用户是否存在
user, err := GetUserByMobile(mobile)

// 3. 如果不存在且允许自动注册
if err != nil && autoRegisterEnabled {
    user = &User{
        Username:    "user_" + mobile[len(mobile)-6:], // 用户名: user_138000
        Mobile:      mobile,
        DisplayName: username,
        Role:        RoleCommonUser,
        Status:      UserStatusEnabled,
    }
    user.Insert(0)
}

// 4. 设置登录Session
setupLogin(user, c)
```

## 五、安全措施

### 5.1 速率限制

| 限制类型 | 限制规则 | 实现方式 |
|---------|---------|---------|
| 全局限流 | 20请求/20分钟 | `middleware.CriticalRateLimit()` |
| 短信频率 | 60秒/次 | `CheckSendFrequency()` |
| 每日上限 | 10次/天 | `TodayIndex` 字段 |

### 5.2 验证码安全

- ✅ **5分钟过期**：配置项 `SmsCodeExpireMinutes`
- ✅ **一次性使用**：验证后标记 `used = true`
- ✅ **场景隔离**：登录/绑定/重置的验证码不能混用
- ✅ **完整匹配**：必须同时匹配 mobile + code + scene

### 5.3 手机号绑定安全

- ✅ **唯一性约束**：一个手机号只能绑定一个账号
- ✅ **绑定前检查**：检查手机号是否已被其他用户占用
- ✅ **重复绑定限制**：已绑定用户需先解绑才能绑定新号码

### 5.4 密码重置安全

- ✅ **权限验证**：仅绑定手机号的用户可重置
- ✅ **密码强度**：8-20位长度验证
- ✅ **防枚举攻击**：即使手机号不存在也返回"验证码已发送"
- ✅ **操作审计**：所有密码重置记录到日志

### 5.5 IP追踪与审计

```go
// 记录创建IP
smsCode.CreateIp = c.ClientIP()

// 记录使用IP
smsCode.UsedIp = clientIp

// 日志记录
model.RecordLog(userId, LogTypeSystem,
    fmt.Sprintf("通过手机号 %s 重置密码", mobile))
```

## 六、配置管理

### 6.1 系统配置项（14个）

| 配置键 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `SmsLoginEnabled` | bool | false | 启用短信登录功能 |
| `SmsCodeLength` | int | 6 | 验证码长度（4或6） |
| `SmsCodeMin` | int | 100000 | 验证码最小值（6位默认100000） |
| `SmsCodeMax` | int | 999999 | 验证码最大值（6位默认999999） |
| `SmsCodeExpireMinutes` | int | 5 | 验证码过期时间（分钟） |
| `SmsSendFrequencySeconds` | int | 60 | 发送频率限制（秒） |
| `SmsMaxSendPerDay` | int | 10 | 每日最大发送次数 |
| `SmsAutoRegisterEnabled` | bool | true | 允许自动注册 |
| `SmsLoginTemplateCode` | string | "" | 登录验证码模板 |
| `SmsBindTemplateCode` | string | "" | 绑定验证码模板 |
| `SmsResetTemplateCode` | string | "" | 重置验证码模板 |
| `SmsBindEnabled` | bool | true | 启用手机号绑定 |
| `SmsResetEnabled` | bool | true | 启用密码重置 |
| `SmsResetClearSessions` | bool | false | 重置后清除所有会话 |

**验证码范围配置说明**：
- 当 `SmsCodeMin` == `SmsCodeMax` 时，将发送固定验证码（便于测试环境）
- 例如：设置 `SmsCodeMin=123456`，`SmsCodeMax=123456`，则所有验证码都是 `123456`
- 生产环境建议使用默认随机范围：`100000-999999`（6位）或 `1000-9999`（4位）

## 十二、常见问题（FAQ）

### Q1: 如何修改验证码有效期？
**A**: 在管理后台修改 `SmsCodeExpireMinutes` 配置项，或在 `.env` 中设置 `SMS_CODE_EXPIRE_MINUTES`。

### Q2: 如何临时禁用短信登录？
**A**: 设置 `sms_login_enabled=false`，原有用户仍可使用密码登录。

### Q3: 如何更换短信服务商？
**A**: 修改 `service/sms_send.go` 中的 `SendVerificationCode()` 函数，替换阿里云SDK调用。

### Q4: 已有用户如何绑定手机号？
**A**: 用户登录后访问个人中心，使用"绑定手机号"功能。

### Q5: 如何查看短信发送成本？
**A**: 查询 `sms_logs` 表，统计发送成功的记录数，结合阿里云单价计算。

```sql
SELECT
    DATE(created_at) as date,
    COUNT(*) as send_count,
    SUM(CASE WHEN send_status = 1 THEN 1 ELSE 0 END) as success_count
FROM sms_logs
WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
GROUP BY DATE(created_at)
ORDER BY date DESC;
```

### Q6: 如何在测试环境使用固定验证码？
**A**: 通过管理后台API将 `SmsCodeMin` 和 `SmsCodeMax` 设置为相同值即可。

例如，设置固定验证码为 `123456`：
```bash
# 方法1：通过API
curl -X PUT http://localhost:3000/api/option/ \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key": "SmsCodeMin", "value": 123456}'

curl -X PUT http://localhost:3000/api/option/ \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key": "SmsCodeMax", "value": 123456}'

# 方法2：在 .env 中配置
SMS_CODE_MIN=123456
SMS_CODE_MAX=123456
```

**注意**：固定验证码仅用于测试环境，生产环境必须使用随机验证码！

### Q7: 如何在前端管理面板中配置SMS参数？
**A**: 所有SMS配置项已经通过现有的 `/api/option/` 接口暴露，前端只需：

1. **获取当前配置**：调用 `GET /api/option/` 获取所有配置项
2. **展示配置表单**：筛选出以 `Sms` 开头的配置项（驼峰命名），渲染为表单
3. **提交更新**：调用 `PUT /api/option/` 逐个更新配置项
4. **配置立即生效**：无需重启后端服务

参考代码见第六章 6.3 节的前端 JavaScript 示例。

### Q8: 验证码范围设置有什么限制？
**A**:
- 验证码范围必须符合设置的长度（`SmsCodeLength`）
- 6位验证码：范围 0-999999（默认 100000-999999）
- 4位验证码：范围 0-9999（默认 1000-9999）
- 如果设置的范围超出长度限制，系统会自动调整为合法范围
- `min` 值大于 `max` 值时，系统会自动交换两者
