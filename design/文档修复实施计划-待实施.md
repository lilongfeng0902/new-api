# New API 文档修复实施计划

## 背景

### 调查结论

经过深入调查，确认了项目 API 文档的生成方式：

**现有文档是通过 Apifox 手动创建并导出的**，关键证据：
- 文件中包含 Apifox 特有的 `"type": "combination"` 安全定义（非标准 OpenAPI）
- Git 历史显示一次性大规模提交（2025-11-30，9199 行新代码）
- 项目中无任何自动化文档生成工具或配置
- 代码中 Swagger 注解极少（仅 `controller/swag_video.go` 有 21 个注解，未被使用）

**严重问题：字段缺失率 40-50%**

| 接口类型 | 缺失率 | 典型缺失字段 |
|---------|--------|-------------|
| Token 管理 | ~47% | `model_limits_enabled`, `model_limits`, `allow_ips`, `group`, `cross_group_retry` 等 8 个字段 |
| Chat Completions | ~40% | 30+ 高级参数（`store`, `safety_identifier`, 缓存、多供应商特性） |

**影响：**
- 用户无法发现 IP 白名单、模型限制等核心功能
- 隐私控制字段未记录（合规风险）
- 多供应商特定参数完全缺失（Claude 网页搜索、Perplexity 搜索过滤器等）

---

## 实施方案概览

### 核心决策

1. **采用 Swaggo** 作为主要文档工具（代码注解自动生成）
2. **双轨制**：Swagger 为源，Apifox 为协作平台
3. **分阶段实施**：P0 缺失字段 → 高级参数 → 质量提升 → 自动化
4. **自动化优先**：CI/CD + Git Hook 强制同步

### 预期收益

| 指标 | 当前 | 目标 | 提升 |
|------|------|------|------|
| 字段覆盖率 | 50-60% | 100% | +40-50% |
| 文档与代码一致性 | 手动维护 | 自动同步 | 100% |
| 新接口文档时间 | 30 分钟 | 5 分钟 | -83% |

### 阶段 4：自动化与集成（2-3 天）

#### 4.1 CI/CD 自动生成文档

**创建文件：.github/workflows/swagger.yml**

```yaml
name: Swagger Documentation CI

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  swagger:
    name: Generate and Validate Swagger Docs
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Code
        uses: actions/checkout@v3

      - name: Set up Go
        uses: actions/setup-go@v3
        with:
          go-version: '>=1.25.1'

      - name: Install Swag CLI
        run: go install github.com/swaggo/swag/cmd/swag@latest

      - name: Generate Swagger Documentation
        run: make swagger

      - name: Check for Uncommitted Changes
        run: |
          if [[ -n $(git status --porcelain docs/swagger) ]]; then
            echo "::error::Swagger documentation is out of date!"
            echo "::error::Please run 'make swagger' and commit the changes."
            exit 1
          fi

      - name: Upload Swagger Artifact
        uses: actions/upload-artifact@v3
        with:
          name: swagger-docs
          path: docs/swagger/
          retention-days: 30
```

#### 4.2 Git Pre-commit Hook

**创建文件：.git/hooks/pre-commit**

```bash
#!/bin/bash

echo "🔍 Running pre-commit checks..."

# 检查 Go 代码修改
if git diff --cached --name-only | grep -q '\.go$'; then
    echo "📝 Detected Go code changes"

    # 重新生成 Swagger 文档
    echo "📚 Regenerating Swagger documentation..."
    make swagger > /dev/null 2>&1

    if [ $? -ne 0 ]; then
        echo "❌ Failed to generate Swagger documentation"
        exit 1
    fi

    # 检查文档是否有变化
    if git diff --name-only | grep -q 'docs/swagger'; then
        echo "📄 Swagger documentation updated"
        git add docs/swagger

        echo "⚠️  Don't forget to sync with Apifox after merge"
    fi
fi

echo "✅ All pre-commit checks passed"
exit 0
```

#### 4.3 Apifox 自动同步

**两种方案：**

**方案 A：CI 自动同步（推荐）**

在 `.github/workflows/apifox-sync.yml` 中配置（仅在 main 分支 push 时触发）：

```yaml
name: Sync to Apifox

on:
  push:
    branches: [ main ]
    paths:
      - 'docs/swagger/swagger.json'

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'

      - name: Install Apifox CLI
        run: npm install -g @apifox/cli

      - name: Sync to Apifox
        env:
          APIFOX_TOKEN: ${{ secrets.APIFOX_API_TOKEN }}
        run: |
          apifox import \
            --project-id ${{ secrets.APIFOX_PROJECT_ID }} \
            --token $APIFOX_TOKEN \
            --file docs/swagger/swagger.json \
            --merge-mode smart
```

需要在 GitHub Secrets 中配置：
- `APIFOX_API_TOKEN`
- `APIFOX_PROJECT_ID`

## 验证策略

### 文档完整性验证脚本

**创建文件：scripts/check_field_coverage.sh**

```bash
#!/bin/bash

echo "检查 Token Schema 字段覆盖率..."

REQUIRED_FIELDS=(
    "model_limits_enabled"
    "model_limits"
    "allow_ips"
    "group"
    "cross_group_retry"
    "used_quota"
    "unlimited_quota"
)

SWAGGER_FILE="docs/swagger/swagger.json"

for field in "${REQUIRED_FIELDS[@]}"; do
    if jq -e ".components.schemas.\"model.Token\".properties.\"$field\"" $SWAGGER_FILE > /dev/null 2>&1; then
        echo "✅ $field - 已包含"
    else
        echo "❌ $field - 缺失"
        exit 1
    fi
done

echo "✅ Token Schema 字段覆盖率检查通过"
```
