# 短信登录功能实施方案

## 概述

为 New API 项目添加基于手机号和短信验证码的登录/注册功能，支持用户通过手机号自动注册，同时保留现有的密码登录方式。

## 核心变更

### 1. 数据库变更

#### 1.1 User 表添加手机号字段
**文件**: `model/user.go`
```go
Mobile string `json:"mobile" gorm:"index" validate:"omitempty,len=11"`
```

#### 1.2 新增短信验证码表 (sms_code)
**文件**: `model/sms_code.go` (新建)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| mobile | varchar(16) | 手机号，索引 |
| code | varchar(10) | 验证码 |
| scene | int | 场景码(1=登录) |
| create_ip | varchar(45) | 创建IP |
| today_index | int | 今日发送次数 |
| used | boolean | 是否已使用 |
| used_time | datetime | 使用时间 |
| used_ip | varchar(45) | 使用IP |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

**索引**:
- `idx_mobile` - 单字段索引
- `idx_mobile_scene_code` - 复合索引用于验证查询

**场景常量**:
```go
const (
    SmsSceneLogin = 1  // 登录/注册
    SmsSceneBind  = 2  // 绑定手机号
    SmsSceneReset = 3  // 密码重置
)
```

#### 1.3 新增短信日志表 (sms_log)
**文件**: `model/sms_log.go` (新建)

记录所有短信发送记录，包括发送状态、阿里云API返回信息等。

#### 1.4 数据库迁移
**文件**: `model/main.go`

在 `migrateDB()` 函数中添加：
```go
&SmsCode{},
&SmsLog{},
```

### 2. 业务逻辑层

#### 2.1 短信验证码服务
**文件**: `service/sms_code.go` (新建)

核心功能：
- `GenerateCode()` - 生成6位随机数字验证码
- `CheckSendFrequency()` - 频率限制检查（60秒间隔，每日10次上限）
- `CreateSmsCode()` - 创建验证码记录
- `ValidateAndUseSmsCode()` - 验证并标记验证码为已使用
- `CleanupExpiredCodes()` - 清理过期验证码

**配置**:
```go
type SmsCodeConfig struct {
    CodeLength           int  // 验证码长度，默认6
    ExpireMinutes        int  // 过期时间，默认5分钟
    SendFrequencySeconds int  // 发送频率，默认60秒
    MaxSendPerDay        int  // 每日上限，默认10
}
```

#### 2.2 短信发送服务
**文件**: `service/sms_send.go` (新建)

- `SendVerificationCode()` - 发送短信并记录日志
- 复用现有的 `common.SendAliyunSMS()` 函数

#### 2.3 用户服务扩展
**文件**: `service/user.go` (新建或扩展)

- `GetUserByMobile()` - 根据手机号查询用户
- `CreateUserWithMobile()` - 创建新用户（用户名: user_[手机后6位]）
- `GetOrCreateUserByMobile()` - 获取或自动注册用户
- `BindMobileToUser()` - 绑定手机号到现有用户
- `ResetPasswordByMobile()` - 通过手机号重置密码
- `CheckMobileAvailable()` - 检查手机号是否可用（未被绑定）

### 3. 控制器层

#### 3.1 短信登录控制器
**文件**: `controller/sms_login.go` (新建)

**1. 发送登录验证码接口**:
```go
func SendSmsCode(c *gin.Context)
```
- 请求: `{"mobile": "13800138000"}`
- 验证手机号格式（中国11位手机号）
- 检查频率限制
- 生成并发送验证码（场景：SmsSceneLogin）
- 返回过期时间

**2. 短信登录接口**:
```go
func SmsLogin(c *gin.Context)
```
- 请求: `{"mobile": "13800138000", "code": "123456"}`
- 验证验证码（场景：SmsSceneLogin）
- 获取或创建用户（自动注册）
- 检查用户状态
- 设置登录会话（复用 `setupLogin()` 函数）

**3. 发送绑定验证码接口**:
```go
func SendBindCode(c *gin.Context)
```
- **需要登录**（使用 middleware.UserAuth()）
- 请求: `{"mobile": "13800138000"}`
- 检查当前用户是否已绑定手机号
- 检查目标手机号是否已被其他用户绑定
- 生成并发送验证码（场景：SmsSceneBind）

**4. 绑定手机号接口**:
```go
func BindMobile(c *gin.Context)
```
- **需要登录**（使用 middleware.UserAuth()）
- 请求: `{"mobile": "13800138000", "code": "123456"}`
- 验证验证码（场景：SmsSceneBind）
- 检查手机号是否已被占用
- 更新 user.mobile 字段
- 记录操作日志

**5. 解绑手机号接口**:
```go
func UnbindMobile(c *gin.Context)
```
- **需要登录**（使用 middleware.UserAuth()）
- 检查用户是否已绑定手机号
- 清空 user.mobile 字段
- 记录操作日志
- 可选：要求密码验证或其他安全验证

**6. 发送重置密码验证码接口**:
```go
func SendResetCode(c *gin.Context)
```
- **无需登录**
- 请求: `{"mobile": "13800138000"}`
- 检查手机号是否存在（已绑定用户）
- 生成并发送验证码（场景：SmsSceneReset）

**7. 重置密码接口**:
```go
func ResetPassword(c *gin.Context)
```
- **无需登录**
- 请求: `{"mobile": "13800138000", "code": "123456", "new_password": "newpass123"}`
- 验证验证码（场景：SmsSceneReset）
- 验证新密码强度（8-20位）
- 更新密码（bcrypt哈希）
- 可选：清除该用户的所有 session（强制重新登录）
- 记录密码重置日志

**辅助函数**:
- `ValidateMobile()` - 验证11位手机号格式
- `ValidatePassword()` - 验证密码强度
- `getSmsLoginEnabled()` - 获取配置
- `getSmsCodeConfig()` - 加载配置

### 4. 路由配置

**文件**: `router/api-router.go`

#### 4.1 公开路由（无需登录）
在 `userRoute` 组中添加：
```go
// 短信登录相关（无需登录）
userRoute.POST("/send-sms-code", middleware.CriticalRateLimit(), middleware.TurnstileCheck(), controller.SendSmsCode)
userRoute.POST("/sms-login", middleware.CriticalRateLimit(), middleware.TurnstileCheck(), controller.SmsLogin)

// 密码重置相关（无需登录）
userRoute.POST("/send-reset-code", middleware.CriticalRateLimit(), middleware.TurnstileCheck(), controller.SendResetCode)
userRoute.POST("/reset-password", middleware.CriticalRateLimit(), middleware.TurnstileCheck(), controller.ResetPassword)
```

#### 4.2 需要登录的路由
在 `selfRoute` 组中添加（该组已有 `middleware.UserAuth()` 中间件）：
```go
// 手机号绑定相关（需要登录）
selfRoute.POST("/send-bind-code", controller.SendBindCode)
selfRoute.POST("/bind-mobile", controller.BindMobile)
selfRoute.POST("/unbind-mobile", controller.UnbindMobile)
```

### 5. 配置管理

#### 5.1 系统配置选项
**文件**: `model/option.go`

添加配置常量：
- `sms_login_enabled` - 是否启用短信登录（默认false）
- `sms_code_length` - 验证码长度（默认6）
- `sms_code_expire_minutes` - 过期时间（默认5）
- `sms_send_frequency_seconds` - 发送频率（默认60）
- `sms_max_send_per_day` - 每日上限（默认10）
- `sms_auto_register_enabled` - 允许自动注册（默认true）
- `sms_login_template_code` - 阿里云短信登录模板code
- `sms_bind_template_code` - 阿里云短信绑定模板code
- `sms_reset_template_code` - 阿里云短信重置模板code
- `sms_bind_enabled` - 是否允许绑定手机号（默认true）
- `sms_reset_enabled` - 是否允许通过短信重置密码（默认true）
- `sms_reset_clear_sessions` - 重置密码后是否清除所有会话（默认false）

**端点**: `POST /api/user/send-sms-code`
**权限**: 无需登录

请求:
```json

    "mobile": "13800138000"
}
```

## 安全措施

1. **速率限制**
   - 全局: `CriticalRateLimit()` - 20请求/20分钟
   - 短信特定: 60秒间隔，每日10次上限（针对同一手机号）

2. **验证码安全**
   - 5分钟过期（可配置）
   - 一次性使用（验证后标记为 used）
   - 场景隔离（scene字段，Login/Bind/Reset 互不干扰）
   - 验证时必须匹配 mobile + code + scene 三个字段

3. **IP追踪**
   - 记录创建IP和使用IP
   - 用于审计和滥用检测
   - 异常IP行为可触发额外验证

4. **用户验证**
   - 禁用用户无法登录和重置密码
   - 自动注册可配置开关

5. **手机号绑定安全**
   - 一个手机号只能绑定一个账号
   - 绑定前检查手机号是否已被占用
   - 已绑定用户尝试绑定其他号码需先解绑
   - 解绑操作需要验证（可选：要求密码）

6. **密码重置安全**
   - 仅绑定手机号的用户可重置密码
   - 新密码必须符合强度要求（8-20位）
   - 重置成功后可选择清除所有会话（强制重新登录）
   - 防止手机号枚举：即使手机号不存在也返回"验证码已发送"
   - 记录所有密码重置操作到日志

7. **防暴力破解**
   - 验证码输入错误次数限制（可扩展）
   - IP黑名单机制（可扩展）
   - 异常行为监控和告警

8. **数据隐私**
   - 短信日志中不记录验证码明文
   - API 响应中不暴露敏感信息
   - 日志记录脱敏处理（手机号中间4位打码）

## 关键决策和权衡

1. **时间字段使用 `time.Time` 而非 Unix时间戳**
   - 理由: 与项目中其他新表（如 TwoFA）保持一致，且 GORM 自动处理更方便

2. **自动注册默认开启**
   - 理由: 符合现代应用习惯，降低注册门槛
   - 可通过配置关闭

3. **复用现有阿里云短信服务**
   - 理由: 已有完整实现，避免重复开发
   - 需配置不同的模板code（登录 vs 额度告警）

4. **手机号仅支持中国11位**
   - 理由: 简化初期实现，与阿里云短信服务匹配
   - 未来可扩展国际号码支持

5. **不使用JWT，继续使用Session**
   - 理由: 保持与现有认证机制一致
   - 复用 `setupLogin()` 函数
